# WhipUp

자취생이 **지금 가진 재료로 만들 수 있는 메뉴**를 빠르게 찾고, 늘 먹던 메뉴에서 벗어나도록 돕는 요리 추천 앱.

## Product

### Problem

냉장고에 재료가 있어도 무엇을 해먹을지 떠오르지 않는다. 새로운 메뉴를 찾으려고 유튜브나 레시피 앱을 뒤져도 탐색에 시간이 들고, 마음에 드는 메뉴를 찾은 뒤에야 필요한 재료가 없다는 것을 알게 되는 경우가 많다. 결국 익숙한 몇 가지 메뉴를 반복하게 된다.

### Target

주 사용자는 집에서 직접 요리하는 1인 가구다. 요리를 싫어하지는 않지만 `오늘 뭐 먹지?`를 자주 고민하고, 새로운 메뉴를 먹고 싶어도 결국 비슷한 음식을 반복해서 먹는 사람을 대상으로 한다.

배달 중심 사용자, 요리를 거의 하지 않는 사용자, 다이어트/영양 관리가 주목적인 사용자, 전문적인 요리를 즐기는 사용자는 MVP의 주요 대상이 아니다.

### Value

사용자의 보유 재료를 기준으로 다음 메뉴를 바로 보여준다.

- 지금 가진 재료만으로 만들 수 있는 메뉴
- 재료 1개를 추가하면 만들 수 있는 메뉴
- 재료 2개를 추가하면 만들 수 있는 메뉴

추천의 핵심은 레시피를 많이 보여주는 것이 아니라 **현재 사용자가 실제로 만들 가능성이 높은 메뉴를 먼저 좁혀주는 것**이다.

### Success

MVP에서 가장 중요한 성공 기준은 **사용자가 앱을 통해 평소 먹지 않던 메뉴를 실제로 해먹는 것**이다.

보조적으로 추천 목록에서 상세로 진입하는 비율, 사용자가 만들어보는 메뉴의 다양성, 재료를 반복해서 갱신하는 사용 여부를 볼 수 있다.

# MVP Requirements

## Login

- 카카오 로그인을 사용한다.
- 최초 로그인 시 서비스 User를 생성한다.
- 사용자 데이터는 계정별로 분리한다.
- 로그인 후 보유 재료가 없으면 최초 재료 등록으로 이동한다.
- 보유 재료가 있으면 추천 화면으로 이동한다.
- 카카오 인증에 실패하면 로그인 상태를 만들지 않는다.

## Ingredient Management

사용자는 서비스에 미리 등록된 canonical Ingredient와 해당 Ingredient Form 중 자신이 가진 재료를 등록한다. 예를 들어 canonical `삼겹살`뿐 아니라 `통삼겹`, `대패삼겹살`처럼 서비스에 등록된 Form 표현도 선택할 수 있다.

- 재료 목록 탐색과 이름 검색을 지원한다.
- 사용자가 임의의 재료를 직접 생성할 수 없다.
- 여러 재료를 선택한 뒤 한 번에 등록할 수 있다.
- 최종 등록 전 선택을 취소할 수 있다.
- 등록하지 않고 화면을 나가면 선택 내용은 저장하지 않는다.
- 동일한 canonical Ingredient라도 서로 다른 Form은 각각 보유 재료로 등록할 수 있다.
- 동일한 `Ingredient + Form` 조합(또는 Form 없는 canonical 자체)은 중복 등록할 수 없다.
- 보유 재료 개수에 제한을 두지 않는다.
- 수량, 중량, 용량은 관리하지 않고 **보유 여부만** 관리한다.
- 조미료도 일반 재료와 동일하게 취급한다.

보유 재료는 **추가와 삭제만 가능하며 수정 기능은 제공하지 않는다.**

삭제는 별도 확인 없이 즉시 반영한다. 마지막 재료도 삭제할 수 있으며, 마지막 재료를 삭제했다고 해서 현재 화면에서 강제로 이동시키지는 않는다. 이후 추천에 진입하거나 앱에 다시 진입했을 때 보유 재료가 0개라면 재료 등록으로 이동한다.

최초 재료 등록을 완료하면 추천 화면으로 이동한다.

## Recommendation

추천은 현재 사용자의 보유 재료와 레시피의 필요 재료를 비교해서 결정한다.

```plain text
missing = recipe required ingredients - user owned ingredients

missing 0 → 지금 바로 가능
missing 1 → 재료 1개 부족
missing 2 → 재료 2개 부족
missing 3+ → 추천 제외
```

- 기본 추천에서는 `지금 바로 가능` 메뉴를 가장 먼저 제공한다.
- 사용자는 100% 가능 메뉴를 모두 확인하지 않아도 1개 부족 / 2개 부족 메뉴를 볼 수 있다.
- 부족 메뉴에는 부족한 재료명을 제공한다.
- 동일한 부족 개수를 가진 레시피끼리의 추가 정렬 기준은 MVP에서 정의하지 않는다.
- 결과가 많으면 추가 결과를 조회할 수 있어야 한다.
- 보유 재료가 변경되면 다음 추천 조회부터 변경된 상태로 다시 계산한다.
- 보유 재료가 0개면 추천하지 않고 재료 등록으로 이동한다.
- 특정 단계의 추천 결과가 없더라도 다른 단계의 결과는 정상적으로 제공한다.

Ingredient Form은 MVP 재료 등록과 표시에는 사용하지만, 추천 가능 여부와 부족 재료 계산에는 사용하지 않는다. 추천은 Form과 무관하게 DISTINCT canonical Ingredient만 비교한다.

MVP 추천 판단에는 다음 요소를 사용하지 않는다.

- 재료 수량 / 중량 / 용량
- 전체 필요 재료 대비 보유 비율
- 재료 중요도
- 필수 / 선택 재료 구분
- 대체 가능한 재료

추천 결과를 탭, 필터, 섹션 중 어떤 UI로 구분할지는 Product Requirement에서 고정하지 않는다.

> 추천 계산의 정확한 canonical Ingredient / Form 처리 규칙은 `../domain/domain.md`를 따른다.

## Recipe Detail

추천된 모든 레시피는 상세 화면에 진입할 수 있다.

상세에서는 다음 정보를 제공한다.

- 전체 필요 재료
- 각 재료의 조리용 양
- 사용자의 현재 보유 / 부족 상태
- 순서가 있는 단계별 조리 방법
- 연결된 유튜브 쇼츠
- 유튜브 쇼츠에서 가져온 레시피 썸네일

재료의 양은 조리를 위한 참고 정보일 뿐 추천이나 보유 여부 판단에는 사용하지 않는다. 예를 들어 레시피가 `삼겹살 400g`을 요구해도 사용자가 삼겹살을 보유 재료로 등록했다면 보유한 것으로 판단한다.

유튜브 쇼츠가 주요 조리 콘텐츠이며 텍스트 조리 방법은 같은 내용을 구조화한 보조 정보다. 상세 진입만으로 영상을 자동 재생하지 않고 사용자가 재생을 선택했을 때 앱 안에서 재생한다.

쇼츠를 재생할 수 없는 경우에도 레시피 상세, 필요 재료, 조리 단계는 사용할 수 있어야 한다.

## Recipe Operations

운영자는 유튜브 쇼츠를 기반으로 레시피 데이터를 만든다. 별도의 관리자용 서비스나 UI는 MVP 요구사항이 아니다.

기본 흐름은 다음과 같다.

1. 운영자가 유튜브 쇼츠 URL을 입력한다.
2. AI가 레시피 초안을 생성한다.
3. 운영자가 초안을 검토하고 수정한다.
4. 추출된 재료를 Ingredient Master와 매핑한다.
5. 필요한 Ingredient가 없다면 Master에 추가한다.
6. 운영자가 최종 확정한다.
7. 확정된 레시피만 서비스에서 사용한다.

기본 운영 흐름에서 AI 초안과 검수 중 데이터는 Repository Dataset 파일로 관리하고, 검증이 완료된 Recipe를 Bulk Import한다. DB의 `DRAFT` 상태는 향후 운영 확장을 위해 허용하지만 MVP 기본 import workflow는 불완전한 Draft를 DB에 저장하지 않는다.

초안에는 최소한 레시피명, 원본 쇼츠, 필요 재료, 재료별 양, 단계별 조리 방법이 포함되어야 한다. 레시피 썸네일은 별도 업로드하지 않고 YouTube Shorts reference를 기준으로 가져온다.

AI가 생성하거나 제안한 내용을 자동으로 최종 확정하지 않는다. 재료 매핑을 포함한 최종 판단은 운영자가 한다. 필수 정보가 누락됐거나 하나라도 Ingredient Master와 매핑되지 않았다면 최종 확정할 수 없다.

쇼츠의 실제 조리 표현은 보존한다. 예를 들어 `다진 마늘 1큰술`을 추천 기준의 `마늘`과 연결하더라도 상세에서 사용할 실제 표현과 양은 유지한다.

동일한 재료로 판단되는 표현은 하나의 Ingredient에 연결할 수 있지만, 단순히 서로 대체 가능하다는 이유로 같은 Ingredient로 취급하지 않는다.

운영자는 확정된 레시피를 수정하거나 삭제할 수 있다. 삭제된 레시피는 이후 추천과 상세에서 제공하지 않는다.

AI 분석이 실패하거나 초안이 불완전한 경우 기존 서비스 데이터에는 영향을 주지 않는다.

## Ingredient Master Operations

운영자는 Ingredient Master를 조회, 추가, 수정할 수 있다.

- 사용자와 레시피가 같은 Ingredient 기준으로 비교될 수 있도록 관리한다.
- 새로운 Ingredient를 추가하기 전에 기존 Ingredient와 동일하게 취급할 수 있는지 확인한다.
- 서로 다른 Ingredient를 병합하는 기능은 MVP에서 제공하지 않는다.
- Ingredient 간 대체 관계를 관리하지 않는다.

# Out of Scope

MVP에서는 다음을 구현하지 않는다.

- 커뮤니티, 댓글, 좋아요, 팔로우, 랭킹
- 장보기 목록 및 쇼핑 서비스 연동
- 냉장고 사진 / 영수증 인식
- 자동 재고 추적
- 칼로리 / 영양 분석 / 다이어트 추천
- 사용자 레시피 등록
- 즐겨찾기
- 재료 대체 추천
- 고도화된 추천 정렬
- 재료의 실제 보유량 추적
