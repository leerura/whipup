# UX

사용자 앱의 화면 구조와 이동 규칙을 정의한다. 운영 데이터 관리는 별도 관리자 UI를 전제로 하지 않으므로 이 문서에서 다루지 않는다.

> 시각 디자인의 최종 기준은 Figma를 따른다. 이 문서는 화면의 역할, 상태, 행동과 이동 규칙을 정의한다.

## Main Journey

```plain text
앱 진입
  ↓
카카오 로그인
  ↓
보유 재료 확인
  ├─ 0개 ─→ 최초 재료 등록 ─→ 추천
  └─ 1개 이상 ─────────────→ 추천
                              ↓
                         레시피 선택
                              ↓
                         레시피 상세
```

로그인 이후의 핵심 사용 흐름은 **재료를 등록하고 → 만들 수 있는 메뉴를 찾고 → 레시피를 확인하는 것**이다.

보유 재료는 별도 관리 화면에서 추가하거나 삭제할 수 있다. 변경된 재료는 이후 추천 조회부터 반영한다.

---

# Information Architecture

```plain text
App
├─ Login
│  └─ Kakao Login
│
├─ Ingredients
│  ├─ Initial Registration
│  └─ Owned Ingredients
│     ├─ View
│     ├─ Add
│     └─ Delete
│
├─ Recommendation
│  ├─ Available Now
│  ├─ Missing 1 Ingredient
│  └─ Missing 2 Ingredients
│
└─ Recipe Detail
   ├─ Required Ingredients
   ├─ Owned / Missing Status
   ├─ Cooking Steps
   └─ YouTube Shorts
```

추천의 `Available Now / Missing 1 / Missing 2`는 서로 다른 화면이 아니라 **하나의 추천 화면에서 탐색하는 결과 그룹**이다. 탭, 필터, 섹션 등 구체적인 표현 방식은 UX 구현에서 변경할 수 있다.

검색 결과 없음, 추천 결과 없음, 영상 재생 실패 같은 예외 역시 별도 화면으로 만들지 않고 해당 화면의 State로 처리한다.

# Screens

## S-01 · Kakao Login

**역할**  
사용자를 식별하고 서비스 이용을 시작한다.

**진입**  
로그인되지 않은 상태로 앱에 진입한 경우.

**주요 UI**

- 카카오 로그인
- 인증 진행 상태
- 인증 실패 안내

**States**

- `Default` — 로그인 가능
- `Loading` — 카카오 인증 진행 중
- `Error` — 인증 실패 또는 계정 정보를 확인할 수 없음

**Navigation**

```plain text
로그인 성공
├─ 보유 재료 0개 → S-02
└─ 보유 재료 1개 이상 → S-04

로그인 실패 → S-01 Error
```

---

## S-02 · Initial Ingredient Registration

**역할**  
보유 재료가 없는 사용자가 첫 재료를 등록하고 추천을 시작할 수 있게 한다.

**진입**

- 로그인 후 보유 재료가 0개인 경우
- 앱 재진입 시 보유 재료가 0개인 경우
- 보유 재료 0개 상태에서 추천에 진입한 경우

**주요 UI**

- 등록 가능한 canonical Ingredient 및 Ingredient Form 목록
- 표시 재료명 검색
- 복수 재료 선택 / 선택 취소
- 선택한 재료 등록

**States**

- `Default` — 재료 목록과 검색 제공
- `Selected` — 하나 이상의 재료 선택
- `No Selection` — 선택 없이 등록할 수 없음
- `No Result` — 검색 결과 없음. 새로운 재료 직접 생성은 불가

**Navigation**

```plain text
재료 1개 이상 등록 → S-04
등록 전 이탈 → 선택 내용 저장 안 함
```

---

## S-03 · Owned Ingredient Management

**역할**  
현재 보유 재료를 확인하고 재료를 추가하거나 삭제한다.

**진입**  
로그인된 사용자가 보유 재료 관리를 시작한 경우.

**주요 UI**

- 현재 보유 재료 목록
- 재료 추가 진입
- 보유 재료 삭제
- 추가 시 재료 목록 / 검색 / 복수 선택

**States**

- `Default` — 현재 보유 재료 표시
- `Add Mode` — 추가할 재료 탐색 및 선택
- `Existing Disabled` — 이미 보유한 동일 `Ingredient + Form` 옵션은 확인 가능하지만 다시 선택 불가. 같은 canonical Ingredient의 다른 Form은 선택 가능
- `No Result` — 검색 결과 없음
- `Empty Owned` — 마지막 재료 삭제 후 보유 재료 0개. 현재 화면 유지

재료 삭제는 별도 확인 없이 즉시 반영한다. 재료 수정 기능은 제공하지 않는다.

**Navigation**

```plain text
추가 / 삭제 → S-03 유지
추천으로 이동
├─ 보유 재료 1개 이상 → S-04
└─ 보유 재료 0개 → S-02
```

## S-04 · Recipe Recommendation

**역할**  
현재 보유 재료를 기준으로 실제로 만들 수 있는 메뉴와 재료를 조금만 추가하면 만들 수 있는 메뉴를 탐색한다.

**진입**

- 로그인 후 보유 재료가 1개 이상인 경우
- 최초 재료 등록을 완료한 경우
- 사용자가 추천 화면으로 이동한 경우

**주요 UI**

- 지금 바로 가능한 메뉴
- 재료 1개 부족 메뉴
- 재료 2개 부족 메뉴
- 부족 재료명
- 레시피 선택
- 추가 결과 조회
- 보유 재료 관리 진입

100% 가능한 메뉴를 우선 보여주되, 사용자가 이를 모두 탐색해야만 1개 부족 / 2개 부족 메뉴에 접근할 수 있는 구조로 만들지 않는다.

**States**

- `Default` — 추천 결과 제공
- `Category Empty` — 특정 부족 단계의 결과만 없음
- `All Empty` — 0개 / 1개 / 2개 부족 레시피가 모두 없음
- `No Ingredients Redirect` — 보유 재료가 0개면 추천을 제공하지 않고 S-02로 이동

**Navigation**

```plain text
레시피 선택 → S-05
보유 재료 관리 → S-03
추가 결과 조회 → S-04 내 결과 확장
```

---

## S-05 · Recipe Detail

**역할**  
선택한 메뉴의 재료와 조리 방법을 확인하고 연결된 쇼츠를 시청한다.

**진입**  
S-04에서 레시피를 선택한 경우. 100% 가능 / 1개 부족 / 2개 부족 레시피 모두 동일하게 진입할 수 있다.

**주요 UI**

- 레시피 정보
- 전체 필요 재료와 양
- 각 재료의 보유 / 부족 상태
- 순서가 있는 조리 단계
- 유튜브 쇼츠
- YouTube Shorts 기반 썸네일

유튜브 쇼츠는 주요 조리 콘텐츠이고 텍스트 조리 단계는 이를 보조한다. 화면 진입만으로 영상을 자동 재생하지 않는다.

**States**

- `Default` — 상세 정보와 재생 가능한 쇼츠 제공
- `Video Playing` — 사용자가 재생을 선택해 앱 내에서 시청 중
- `Video Error` — 쇼츠를 재생할 수 없음. 재료와 조리 방법은 계속 제공

**Navigation**

```plain text
뒤로 / 추천 탐색 → S-04
보유 재료 변경 필요 → S-03
```

# Navigation Rules

화면 이동에서 반드시 지켜야 하는 규칙만 정리한다.

1. **보유 재료 0개 상태에서는 추천 결과를 보여주지 않는다.** S-02로 이동한다.
2. **최초 재료 등록 완료 후에는 추천으로 이동한다.**
3. **마지막 재료를 삭제해도 S-03에서 강제로 이동시키지 않는다.** 이후 추천 진입 시 S-02로 이동한다.
4. **추천의 세 부족 단계는 S-04 안에서 자유롭게 탐색할 수 있어야 한다.**
5. **모든 추천 레시피는 동일한 S-05 상세 화면으로 진입한다.**
6. **검색 결과 없음, 추천 결과 없음, 영상 오류는 별도 Screen이 아니라 State로 처리한다.**

# UX Boundaries

이 문서는 다음 기능을 전제로 화면이나 navigation을 추가하지 않는다.

- 마이페이지
- 즐겨찾기
- 레시피 검색
- 장보기
- 커뮤니티
- 사용자 레시피 등록
- 재료 수량 관리
- AI 챗봇
- 대체 재료 추천
- 영양 / 칼로리 기능

운영자의 레시피 초안 생성, 검토, Ingredient Master 관리 역시 일반 사용자 앱 Screen 범위에 포함하지 않는다.

Ingredient Form은 재료 등록/표시 UX에 포함한다. 예를 들어 `삼겹살`, `통삼겹`, `대패삼겹살`을 각각 선택 가능한 옵션으로 제공할 수 있다. 추천 계산에서 Form 호환성을 판단하지 않는 것은 Backend Domain Rule이며 UX에서 이를 별도 계산하지 않는다.
