# V3 재료 등록 UX 원칙

## 그룹과 보유 항목 구분

재료 그룹은 검색·탐색과 항목 묶음을 위한 UI다. 그룹 제목은 접고 펴는 역할만 하며, 그 자체를 선택 상태나 보유 수량처럼 보이게 하지 않는다. 실제 보유 상태는 선택 가능한 항목에만 표시한다.

그룹 제목은 사용자에게 익숙한 재료명을 사용한다. `삼겹살 종류`, `마늘 형태`처럼 내부 분류 설명을 제목에 덧붙이지 않는다. 그룹 제목과 선택 항목의 표시명이 같을 수 있으므로, 제목과 선택 항목은 계층, 간격, 선택 컨트롤 등 시각 구조로 구분한다.

## 선택 항목

선택 항목은 사용자가 실제 보유한다고 인식할 수 있는 단위로 작성한다. 모든 그룹에 동일한 규칙을 기계적으로 적용하지 않는다.

아래 항목들은 서로 다른 분류 결과를 설명하는 예시이며, 선택 항목 전체 목록이나 템플릿이 아니다. 다른 재료를 추가할 때 예시의 표면적인 모양을 복제하지 말고 제품 문서의 판단 기준을 적용한다. 기준만으로 정하기 어려우면 임의로 선택 항목을 만들지 않고 결정 요청을 남긴다.

예:

- `마늘` 그룹: `통마늘`, `다진 마늘`
- `간장` 그룹: `진간장`, `국간장`, `양조간장`. 그룹 제목과 같은 `간장` 보유 항목은 두지 않는다.
- `삼겹살` 그룹: `삼겹살`, `대패삼겹살`. 여기서 `삼겹살`은 선택 가능한 실제 부위 단위다.

보유 형태를 모른다는 항목이나 `형태 미지정` 선택지를 제공하지 않는다.

## 선택 상태

선택 상태는 각 보유 항목에 표시한다. 그룹의 펼침/접힘 상태와 보유 상태를 혼동하게 하지 않는다. 같은 그룹 아래의 구체 항목은 여러 개를 동시에 선택할 수 있다. 예: 진간장과 국간장을 모두 보유하거나, 통마늘과 다진 마늘을 모두 보유할 수 있다.

## 레시피 상세의 요구명과 보유 항목 표시

레시피 상세의 재료 목록은 Recipe source의 요구 이름을 그대로 주 이름으로 표시한다. 매치 결과가 해당 요구와 다른 이름의 구체 보유 항목으로 충족되면, 체크 표시만으로 끝내지 말고 보유 항목명을 보조 문구로 함께 보여준다.

예시 형식:

```text
✓ 간장 1큰술
  보유한 진간장으로 만들 수 있어요
```

위 예시는 표기 구조를 설명한다. 각 Recipe의 실제 source 표현과 accepted owned item을 개별 매치 결과에 따라 표시한다. 원문 요구명을 `진간장`으로 덮어쓰거나, 진간장이 모든 레시피의 간장 요구를 충족한다는 전역 문구를 사용하지 않는다. 보유 항목명이 요구명과 같다면 중복 보조 문구는 생략할 수 있다. Substitute와 Preparation은 기존의 명시적 안내 문구를 유지한다.

이 차이는 충족 여부를 이해하는 데 필요한 세부 정보이므로 레시피 상세에서 제공한다. 추천 카드의 요약 문구에 모든 충족 매치를 나열하지 않는다.

## 현재 화면에서 확인한 문제

시뮬레이터의 현재 재료함은 그룹 행에 `마늘`과 `1개 보유`를 표시하고, 펼친 안쪽에 선택 항목 `다진 마늘`과 별도 `마늘`을 보여준다. 간장도 `간장` 그룹 안에 `간장`과 `진간장`이 함께 나타난다. 이 구조는 그룹명과 실제 보유 항목의 의미가 중복되어 보일 수 있다.

V3 화면에서는 그룹 머리글을 선택 가능한 보유 항목처럼 보이지 않게 구분하고, 그룹 안에는 등록 가능한 보유 항목만 표시한다.
