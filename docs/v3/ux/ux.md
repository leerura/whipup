# V3 재료 등록 UX 원칙

## 홈과 추천 화면의 역할

홈은 앱을 열었을 때 사용자가 현재 보유 재료로 무엇을 만들 수 있는지 빠르게 발견하고 다음 행동으로 이동하는 시작 화면이다. 추천 화면은 전체 레시피 후보를 살펴보고 비교·선택하는 화면이다. 홈은 추천 결과 전체를 반복하지 않고 아래 미리보기만 제공한다.

화면 기준은 Figma의 [보유 재료가 있는 홈](https://www.figma.com/design/duKRNE3kpKMhItEbtq9WXz/%EB%83%89%EC%9E%A5%EA%B3%A0-%ED%84%B8%EC%9D%B4-%F0%9F%8D%9A?node-id=375-3)과 [기존 사용자의 빈 재료함 홈](https://www.figma.com/design/duKRNE3kpKMhItEbtq9WXz/%EB%83%89%EC%9E%A5%EA%B3%A0-%ED%84%B8%EC%9D%B4-%F0%9F%8D%9A?node-id=375-4)을 따른다.

빈 재료함 화면의 승인된 레이아웃은 [V3-H05 메인 시안](https://www.figma.com/design/duKRNE3kpKMhItEbtq9WXz/%EB%83%89%EC%9E%A5%EA%B3%A0-%ED%84%B8%EC%9D%B4-%F0%9F%8D%9A?node-id=393-261)이며, 짧은 화면에서는 [V3-H06 스크롤 점검](https://www.figma.com/design/duKRNE3kpKMhItEbtq9WXz/%EB%83%89%EC%9E%A5%EA%B3%A0-%ED%84%B8%EC%9D%B4-%F0%9F%8D%9A?node-id=393-331)을 따른다. 기존 문구, 일러스트, CTA를 유지하고 제목·설명·일러스트·CTA·보조문구의 여백과 배치를 이 시안에 맞춘다. 상단 브랜드와 하단 탭은 고정 영역으로 유지하고, 콘텐츠 높이가 viewport를 넘으면 그 사이 콘텐츠만 스크롤한다.

보유 재료 요약은 홈의 추천 카드와 같은 흰색 표면 및 얇은 테두리의 카드로 표시한다. 별도 강조색 배경을 사용하지 않는다. 시각 참고는 [재료함 카드 대안](https://www.figma.com/design/duKRNE3kpKMhItEbtq9WXz/%EB%83%89%EC%9E%A5%EA%B3%A0-%ED%84%B8%EC%9D%B4-%F0%9F%8D%9A?node-id=384-144)이다.

- `AVAILABLE` 결과에서 최대 2개를 `바로 만들 수 있어요` 섹션에 표시한다.
- `MISSING_INGREDIENTS` 결과 중 `missingCount == 1`인 후보가 있으면 최대 1개를 `재료 한 가지만 더 있으면 돼요` 섹션에 표시한다. `missingCount`는 부족한 재료 낱개가 아니라 충족되지 않은 필수 Requirement 수다. 이 섹션은 1개 Requirement만 충족하면 만들 수 있는 후보를 뜻한다.
- 각 레시피 카드를 누르면 해당 레시피 상세로 이동한다. 전체 추천 보기 동작은 추천 탭으로 이동한다.
- 보유 재료가 있는 홈에는 재료 관리로 이동하는 진입점을 하나 제공한다. 부족 재료 표시는 추가 버튼처럼 보이지 않게 한다.
- 온보딩을 마친 사용자가 보유 재료를 모두 삭제해 빈 상태가 되면 레시피 미리보기 대신 빈 재료함 안내와 `재료 다시 담기` 동작 하나를 표시한다. 이 동작은 온보딩을 반복하지 않고 재료 관리 화면으로 이동한다. 첫 사용자에게는 홈 빈 상태를 보여주지 않고 온보딩의 초기 재료 등록 흐름을 사용한다.
- 추천 화면에서 보유 재료가 0개이면 추천 API 오류로 표시하지 않는다. 추천 결과가 없는 상태와 구분해 재료함이 비어 있음을 안내하고, 기존 빈 상태 스타일과 `재료 등록하기` 동작으로 재료 관리 화면에 연결한다. 보유 재료가 있는 경우의 실제 API 실패는 재시도 가능한 오류 상태로 표시한다.
- 홈·재료·추천 화면의 상단 `whippy` 로고 영역 높이는 52px로 통일한다. 로고를 누르면 홈으로 이동한다.
- 재료 화면의 상단 헤더에는 `whippy` 로고만 표시한다. 동작이 정의되지 않은 알림 및 프로필 버튼은 표시하지 않는다.

온보딩 완료 여부는 현재 보유 재료 수와 별도로 계정에 저장한다. 첫 보유 재료 등록이 성공하면 완료로 기록하고, 이후 보유 재료를 모두 삭제해도 완료 상태를 되돌리지 않는다. 따라서 앱을 다시 열거나 다른 기기에서 로그인해도 온보딩을 반복하지 않는다.

조건에 맞는 후보가 없으면 해당 미리보기 섹션을 표시하지 않는다. 추천 탭은 전체 `AVAILABLE` 및 `MISSING_INGREDIENTS` 탐색과 빈 결과 안내를 담당한다.

## 그룹과 보유 항목 구분

재료 그룹은 검색·탐색과 항목 묶음을 위한 UI다. 그룹 제목은 접고 펴는 역할만 하며, 그 자체를 선택 상태나 보유 수량처럼 보이게 하지 않는다. 실제 보유 상태는 선택 가능한 항목에만 표시한다.

그룹 제목은 사용자에게 익숙한 재료명을 사용한다. `삼겹살 종류`, `마늘 형태`처럼 내부 분류 설명을 제목에 덧붙이지 않는다. 그룹 제목과 선택 항목의 표시명이 같을 수 있으므로, 제목과 선택 항목은 계층, 간격, 선택 컨트롤 등 시각 구조로 구분한다.

## 선택 항목

선택 항목은 사용자가 실제 보유한다고 인식할 수 있는 단위로 작성한다. 모든 그룹에 동일한 규칙을 기계적으로 적용하지 않는다.

아래 항목들은 서로 다른 분류 결과를 설명하는 예시이며, 선택 항목 전체 목록이나 템플릿이 아니다. 다른 재료를 추가할 때 예시의 표면적인 모양을 복제하지 말고 제품 문서의 판단 기준을 적용한다. 기준만으로 정하기 어려우면 임의로 선택 항목을 만들지 않고 결정 요청을 남긴다.

예:

- `마늘` 그룹: `통마늘`, `다진 마늘`
- `간장` 그룹: `진간장`, `국간장`, `양조간장`. 그룹 제목과 같은 `간장` 보유 항목은 두지 않는다.
- `삼겹살` 그룹: `삼겹살`, `대패삼겹살`. 여기서 `삼겹살`은 선택 가능한 실제 부위 단위다.

보유 형태를 모른다는 항목이나 `형태 미지정` 선택지를 제공하지 않는다.

## 선택 상태

선택 상태는 각 보유 항목에 표시한다. 그룹의 펼침/접힘 상태와 보유 상태를 혼동하게 하지 않는다. 같은 그룹 아래의 구체 항목은 여러 개를 동시에 선택할 수 있다. 예: 진간장과 국간장을 모두 보유하거나, 통마늘과 다진 마늘을 모두 보유할 수 있다.

## 레시피 상세의 요구명과 보유 항목 표시

레시피 상세의 재료 목록은 Recipe source의 요구 이름을 그대로 주 이름으로 표시한다. 매치 결과가 해당 요구와 다른 이름의 구체 보유 항목으로 충족되면, 체크 표시만으로 끝내지 말고 보유 항목명을 보조 문구로 함께 보여준다.

예시 형식:

```text
✓ 간장 1큰술
  보유한 진간장으로 만들 수 있어요
```

위 예시는 표기 구조를 설명한다. 각 Recipe의 실제 source 표현과 accepted owned item을 개별 매치 결과에 따라 표시한다. 원문 요구명을 `진간장`으로 덮어쓰거나, 진간장이 모든 레시피의 간장 요구를 충족한다는 전역 문구를 사용하지 않는다. 보유 항목명이 요구명과 같다면 중복 보조 문구는 생략할 수 있다. Substitute와 Preparation은 기존의 명시적 안내 문구를 유지한다.

이 차이는 충족 여부를 이해하는 데 필요한 세부 정보이므로 레시피 상세에서 제공한다. 추천 카드의 요약 문구에 모든 충족 매치를 나열하지 않는다.

## 추천 카드의 부족 재료와 높이

추천 카드의 부족 재료 요약은 사용자가 재료함에서 찾을 수 있는 짧은 이름을 우선한다. 레시피 source가 특정 selectable item과 정확히 연결된 경우 해당 item의 표시명을 쓴다. 예를 들어 `순살 닭다리 정육` source가 보유 항목 `닭다리살`에 정확히 연결되면 카드에는 `닭다리살`이 필요하다고 표시한다. source 표현과 추출 근거는 dataset에 그대로 보존하며, 상세 화면은 source 이름과 실제 매치 설명을 보여준다.

포괄적인 source 요구가 여러 selectable item으로 충족될 수 있어 하나의 item 이름으로 축약할 수 없는 경우에는 source 요구명을 사용한다. 추천 카드에는 가능한 보유 항목을 전부 나열하지 않는다. 자세한 충족/대체 정보는 레시피 상세에서 확인한다.

추천 카드는 2열 masonry 흐름을 사용해 카드마다 실제 콘텐츠 높이를 따른다. 제목과 부족 재료 안내는 각각 한 줄로 제한하고 넘치는 문구는 말줄임 표시한다. 카드에 보조 설명을 예약 공간으로 남기거나, 충족 매치와 대체 설명을 길게 나열하지 않는다. 자세한 정보는 레시피 상세에서 제공한다. 열별 카드 높이와 아래선은 달라도 되며, 짧은 카드 안에 빈 텍스트 영역을 강제로 만들지 않는다.

## 레시피 영상 재생과 스크롤

레시피 상세 상단의 영상 썸네일에는 재생 버튼을 표시한다. 사용자가 재생하면 레시피 상세 안에서 영상을 재생한다.

영상 재생 중 사용자가 영상 영역 아래로 스크롤하면 플레이어를 앱바 바로 아래 오른쪽에 고정된 PIP로 접고 재생을 이어간다. 일반적인 모바일 너비에서는 16:9 약 356×200 logical px로 표시해 YouTube 임베드의 최소 viewport 200×200px를 충족한다. 좁은 화면에서는 viewport 높이를 200px로 유지하고 가용 폭 안에 표시한다. 가용 폭이 200px 미만이면 PIP를 고정하지 않고 영상을 원래 스크롤 위치에 둔다. YouTube 기본 플레이어 컨트롤을 그대로 사용하며, 플레이어 위에 앱 전용 버튼이나 탭 영역을 겹치지 않는다. 전체 화면 전환과 일시 정지는 YouTube 플레이어 컨트롤에 맡긴다. 상세 화면에서 영상 위치로 다시 스크롤하면 인라인 크기로 돌아간다. 상세 화면을 벗어나면 재생을 종료한다.

Figma의 [상단 우측 PIP 시안](https://www.figma.com/design/duKRNE3kpKMhItEbtq9WXz/%EB%83%89%EC%9E%A5%EA%B3%A0-%ED%84%B8%EC%9D%B4-%F0%9F%8D%9A?node-id=387-56)은 V2 상세 화면 레이아웃을 바탕으로 한 PIP 동작·배치 참고다. 전체 화면 구성은 V3 상세 UI의 구현 기준이 아니다.

## 현재 화면에서 확인한 문제

시뮬레이터의 현재 재료함은 그룹 행에 `마늘`과 `1개 보유`를 표시하고, 펼친 안쪽에 선택 항목 `다진 마늘`과 별도 `마늘`을 보여준다. 간장도 `간장` 그룹 안에 `간장`과 `진간장`이 함께 나타난다. 이 구조는 그룹명과 실제 보유 항목의 의미가 중복되어 보일 수 있다.

V3 화면에서는 그룹 머리글을 선택 가능한 보유 항목처럼 보이지 않게 구분하고, 그룹 안에는 등록 가능한 보유 항목만 표시한다.
