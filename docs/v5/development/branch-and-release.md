# 브랜치와 릴리스

1인 개발이므로 브랜치를 자주 옮기지 않는다.

## 브랜치

- 버전 작업은 **`v5` 브랜치 하나**에서 한다(`docs/v5`와 맞춘다). 기능마다 브랜치를 새로 만들지 않는다.
- `main`은 **배포 반영용**이다. 사이트 자동 배포(GitHub Pages)는 `main`에서만 동작하므로, 웹이나 데이터를 반영할 때 `v5`를 `main`에 PR로 병합한다. 병합한 뒤에도 계속 `v5`에서 작업한다.
- 운영 서버(Windows)는 `v5`를 받아 데이터를 임포트한다.

## 릴리스와 태그

- 앱을 제출할 때마다 제출한 커밋에 `app-v{버전}` 태그를 붙인다(예: `app-v1.0.0`은 출시된 1.0.0 빌드의 커밋).
- 서버를 배포할 때 필요하면 `backend-v{버전}` 태그를 붙인다.
- 작은 수정 묶음(1.0.x)을 큰 기능(1.1.0)보다 먼저 내야 하면, 수정 커밋을 `v5`의 앞쪽에 두고 그 커밋에 태그를 붙여 빌드한다.
- 이미 배포된 앱에 긴급 수정이 필요하고 `v5`가 아직 출시할 수 없는 상태이면, 해당 태그에서 임시 `hotfix/…` 브랜치를 만들어 수정하고 새 태그를 붙인다.

## 규칙

- 서버 API는 구버전 앱이 계속 동작하도록 추가만 하고 기존 동작을 바꾸지 않는다.
- 레시피 삭제나 비공개 처리는 `v5`에서 반영한 뒤 `main`에 병합해야 사이트에서도 내려간다.
