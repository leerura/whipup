# 레시피 영상 수집

pipeline이 처리할 영상 URL을 사람이 하나씩 찾지 않고, 정해 둔 채널의 Shorts에서 후보를 골라 `tools/data-pipeline/input/shorts-urls.txt`에 추가한다. 이후 Gemini 추출과 데이터 반영은 [V3 recipe pipeline](../../v3/development/recipe-pipeline.md)과 [레시피 데이터 반영 가이드](recipe-data-guidelines.md)를 따른다. 이 문서는 후보를 **고르는 기준**만 정한다.

## 채널

- 채널은 `tools/data-pipeline/input/discovery-channels.txt`에 채널 ID로 적는다. 이미 공개된 레시피가 나온 채널 중 구독자가 많은 채널부터 고른다.
- 현재 채널: 1분요리 뚝딱이형, 자취요리신, 유지만, 김진순 점심시간, 살림팝.

## 후보 기준

`python3 tools/data-pipeline/src/discover.py`는 YouTube Data API 키 없이 공개 채널 페이지만 읽는다. 기본은 목록만 출력하고, `--write`를 주면 URL 파일 끝에 주석과 함께 추가한다.

- 조회수 10만 이상(`--min-views`).
- 이미 URL 목록(주석 처리된 것 포함)이나 최종 dataset에 있는 영상은 제외한다.
- 제목에 먹방, 브이로그, 광고, 협찬 같은 단어가 있으면 제외한다.
- oEmbed로 외부 재생이 가능한 영상만 남긴다([제품 기준](../product/product.md)).
- 채널당 조회수 순으로 최대 12개(`--per-channel`).
- 채널 페이지 구조가 바뀌어 목록을 읽지 못하면 오류로 멈춘다.

## 키워드로 찾기 (한식 밖의 요리)

채널 목록은 한식 쪽에 치우쳐 있으므로 파스타·양식·일식·중식처럼 다른 종류의 요리는 **검색어**로 찾는다. `discover.py --query "파스타 레시피"`처럼 검색어를 주면(여러 번 줄 수 있다) 유튜브 공개 검색 결과에서 후보를 읽는다. 기본은 목록만 출력하고 `--write`를 주면 URL 파일에 추가하는 것은 채널 방식과 같다.

- 후보를 거르는 기준은 **영상 조회수가 아니라 채널 규모(구독자 수)**다. 구독자 30만 명 이상(`--min-subs`)인 채널의 영상만 남긴다. 구독자 수는 채널 페이지에서 읽으며, 읽지 못한 채널은 제외한다. 조회수는 `--min-views`로 따로 걸 수 있고 기본은 걸지 않는다.
- 길이 3분 이하 영상 중 쇼츠로 열리는 것만 남긴다. 그 밖의 기준(이미 있는 영상 제외, 제목 제외 단어, 외부 재생 가능 여부)은 채널 방식과 같다.
- 검색어당 구독자 수 순으로 최대 10개(`--per-query`).
- 새 종류의 요리는 기존 재료 마스터에 없는 재료가 나올 수 있다. 수집 단계에서는 거르지 않고, 추출한 뒤 **새로 필요한 재료 목록을 사람이 보고 추가 여부를 정한다.** 정하기 전까지 해당 레시피는 초안으로 둔다.

재료 수, 특수 재료, 만드는 법 유무는 영상을 보기 전에는 알 수 없으므로 수집 단계에서 거르지 않는다. 이 판단은 데이터 반영 단계의 [공개하지 않는 레시피 기준](recipe-data-guidelines.md#5-공개하지-않는-레시피)을 따른다.

## 쇼츠만 처리한다

앱은 YouTube Shorts 레시피 서비스이므로 쇼츠가 아닌 영상은 레시피로 두지 않는다.

- 쇼츠 여부는 `youtube.com/shorts/{영상ID}`가 그대로 열리는지(쇼츠), `/watch`로 넘어가는지(일반 영상)로 판단한다. 수집 후보는 채널의 쇼츠 탭에서만 가져온다.
- pipeline은 Gemini를 호출하기 전에 이 확인을 한다. 쇼츠가 아니면 `SKIPPED_NOT_SHORT`로 표시하고 Gemini 쿼터를 쓰지 않는다. 확인하지 못하면(네트워크 오류) 건너뛰지 않고 그대로 진행한다.
- URL을 사람이 직접 추가해도 같은 확인이 적용된다. 쇼츠가 아닌 영상은 이미 추출됐더라도 데이터에 반영하지 않는다.
